# Codebase Concerns & Technical Debt

**Analysis Date:** 2026-09-09

This document outlines known issues, technical debt, security concerns, and performance bottlenecks identified in the Nexus AI codebase.

## 1. Technical Debt & Code Smells

- **Misplaced Files:** `WebsocketClient.cpp` and `WebSocketClient.h` are incorrectly located inside the `backend/` directory instead of the root or frontend directory.
- **Poor Logging Practices:** Extensive use of raw `print()` statements across the Python backend (`test_imap.py`, `test_service.py`, `test_router.py`, `api/email/context.py`, `tasks/seed_demo.py`). The established `logging` framework in `server.py` and `config.py` is ignored in many modules.
- **Hardcoded Configuration:**
  - `backend/core/config.py` hardcodes the local model to `llama-3.2-3b-instruct.gguf`.
  - C++ and `server.py` rely on hardcoded WebSocket URLs (`ws://127.0.0.1:8000/ws`).
- **Test File Organization:** Test scripts (`test_*.py`) are scattered throughout `backend/` and `backend/memory/` rather than being contained in a dedicated `tests/` directory.
- **Coupling of UI and Backend:** The backend controls frontend animations directly via hardcoded state commands (`compact`, `expanded`) with brittle `asyncio.sleep(0.15)` delays between transitions in `server.py`.

## 2. Performance Bottlenecks

- **Blocking Sync Calls in Async Loop:** In `backend/api/server.py`, `AIManager.generate_stream()` is a synchronous generator but is called within the FastAPI `async def websocket_endpoint` using a synchronous `for` loop. This blocks the main Starlette event loop during the entire inference process, destroying concurrency and making the server unable to handle other requests or heartbeats.
- **Context Window Mismatch:** `AIManager` initializes the model with a large context size (`n_ctx=16384`), but `ConversationHistory` limits history to just 10 messages. This might lead to high memory usage with no practical benefit, or aggressive truncation that wastes the allocated context.

## 3. Known Bugs

- **UI Rendering & Layout:** As documented in `README_PROG.md`, there are bugs in `DynamicIslandWindow.cpp` regarding layout resizing, response label visibility, and state transitions. The `updateExpandedHeight()` logic conflicts with dynamic streaming text insertions.
- **Brittle Markdown Parsing:** `DynamicIslandWindow::markdownToHtmlFragment` relies on a naive regular expression (`<body[^>]*>([\\s\\S]*)</body>`) to parse Qt's HTML output, which is fragile and likely responsible for missing or malformed UI rendering.
- **Unused Hardcoded Data:** In `backend/api/server.py`, a `progress_items` checklist is hardcoded in the WebSocket loop but is never actually serialized or sent to the client.

## 4. Security Concerns

- **Unauthenticated WebSocket:** The local WebSocket server (`/ws` on port 8000) does not require an authentication token or origin validation. Any local process or potentially malicious script (e.g., via a browser accessing localhost) could connect and abuse the local LLM.
- **No Sanitization of LLM Output:** The frontend's reliance on `QTextDocument` and regex to parse LLM output may open up HTML injection vectors if the model hallucinates or maliciously structures HTML tags that bypass basic escaping.
